# FantasyBosses v0.7.2.3 — 세계수 전장 이동 시스템

소스 ZIP입니다. JDK 21 / NeoForge 1.21.1 / GeckoLib NeoForge 4.7.6 / Gradle 9.2.1. 기존에 사용자 테스트를 통과한 v0.7.1 빌드 수정본 기준입니다. 현재 작성 환경에서 외부 Gradle 서버 DNS 연결이 불가능하여 의존성 기반 컴파일이나 인게임 검증은 하지 못했습니다.

## 빌드 및 설치
1. ZIP 압축 해제 후 build_windows.cmd 실행. 기존 프로젝트의 .build-tools 폴더를 새 프로젝트에 복사하면 Gradle 재다운로드를 피할 수 있습니다. Windows 자동 빌드 SHA-256 처리 수정본 유지.
2. 성공 시 build/libs/fantasybosses-0.7.2.3.jar 생성. 오류 시 build-output.log를 전달하세요.
3. 게임 종료 후 mods 폴더의 fantasybosses-0.7.2.2.jar 또는 이전 버전 JAR를 제거하고 새 JAR를 넣습니다. 기존 GeckoLib JAR는 유지. 중복 설치 금지.
4. 기존 데이터팩 보스가 있다면 먼저 /function radicion:stop 실행. 월드를 백업하고 데이터팩을 제거하거나 비활성화하세요. 데이터팩 보스와 정식 보스를 동시에 실행하지 마세요.

## 세계수 전장에서 테스트 (MagicCity dimension required)
- /execute in magiccity:kingdom run tp @s -2860.5 9 -835.5
- /summon fantasybosses:radicion -2861.179 9.518 -884.502
- 소환 시 세계수 전장 안이면 지상 경로 자동 초기화. 전장 청크 로딩 대기 후 필요할 때 start 명령을 사용하세요. 외부 월드에서는 v0.7.1 정지 프리뷰로 유지합니다.

아래 명령어의 대상 선택자: @e[type=fantasybosses:radicion,limit=1,sort=nearest]
- /fantasybosses route <target> start : 전장 지상 경로 초기화 (시작점으로 이동)
- /fantasybosses route <target> air : 지상 연결점에서 벽/천장 순환을 1회 실행, 지상 복귀
- /fantasybosses route <target> dive : 지상 연결점에서 상승, 천장 지정 지점 1.5초 대기, 직접 낙하, 지상 복귀
- /fantasybosses route <target> pause / resume : 정지/재개
- /fantasybosses route <target> groggy : 현재 지상 위치에서 5초 강제 그로기 테스트, 노란 체력바/초 표시.
- /fantasybosses route <target> status : 경로/프레임/대기/예약/청크 상태
- /kill @e[type=fantasybosses:radicion] : 정식 엔티티 제거 (현재 실제 사망은 바닐라)

지상 순환 204틱(10.2초), 공중 순환 260틱(13초), 낙하 42틱(2.1초), 착지 후 그로기 100틱(5초). 20 TPS 기준, 공중 예약은 지상 연결점까지 최대 10.2초 대기. 공격 피해는 v0.7.3에서 추가하므로 공중 이동은 명령어로만 발동합니다. 기존 프리뷰 명령은 전장 밖에서 사용 가능(visual only).

## 구조 및 검증
- 기존 모델/애니메이션/텍스처/발광/Blockbench/원본 포즈 파일은 바이트 단위 보존. 새 route geometry는 기존 182개 큐브 크기와 UV를 재사용하며, 독립 본에 원본 월드 변환을 직접 적용합니다.
- 서버는 실제 머리 위치를 이동시키고 이전/현재 포즈 번호를 SynchedEntityData로 전송합니다. 클라이언트는 월드 좌표 보간 및 직접 쿼터니언 렌더링, 하단 다리의 불필요한 180도 뒤집힘을 대칭 회전 보간으로 방지. 서버 이동/피격박스와 시각 포즈는 네트워크 보간 차이가 생길 수 있습니다.
- 이동 상태/요청/정지 상태를 NBT에 저장. 로드되지 않은 몸통 마디 청크로 진입하지 않도록 정지. 원래 월드 경로를 사용하며 실시간 장애물 탐색 및 지형 변경 대응은 미구현. 기존 지역의 지형을 변경하지 마세요.
- 전장 내 이동 시 중력/일반 블록 이동 물리를 끄고 캡처 경로를 재생합니다. 원본 레지온은 수정하지 않습니다. 이동 중 지형 충돌이나 렌더링 방향/위치는 게임에서 재검증해야 합니다.
- 임시 머리 피격박스 2×2.3 블록 유지. 다중 피격은 v0.7.4, 공격 및 전장 기믹은 각각 v0.7.3/0.7.5.
- Java 구문 파싱 및 바이너리 데이터 구조, 기존 리소스 동일성, 경로 연결점 및 상태 전환 시뮬레이션을 검사했습니다. 실제 컴파일/런타임/멀티플레이 검증은 하지 못했습니다.

## v0.7.2.1 렌더링 수정 (유지)
- 기존 지상/벽/천장/낙하 경로와 서버 이동 로직은 그대로 유지합니다.
- 라우트 전용 렌더러가 직접 quaternion을 적용하여 Euler 변환과 기본 몸 회전을 제거합니다. 일반 프리뷰는 원래 렌더러를 사용합니다.
- 하단 다리 18개의 회전 보간을 수정했습니다. 원본 프레임에서 직육면체의 모양은 보존되며, 표면 텍스처 방향은 일부 달라질 수 있습니다.
- 위치 패킷과 포즈 프레임의 보간 기준을 통일했습니다. 실제 피격 위치의 네트워크 지연 자체는 남을 수 있습니다.
- 기존 JAR를 제거하고 새 JAR만 설치하세요. 컴파일 및 인게임 확인은 필요합니다.

## v0.7.2.2 끊김 개선
- 서버 경로/속도/포즈 바이너리는 그대로 유지. 서버의 경로 시계와 초기화 세대를 동기화하고 클라이언트 틱 기준 약 3틱(150ms, 20TPS)의 포즈 버퍼로 재생. 패킷 지연/묶음 수신 때 이전 프레임부터 다시 시작하던 현상을 줄이도록 설계. 장시간 서버가 멈추면 마지막 수신 자세에서 멈춤.
- 렌더러는 보간한 182개 파츠 변환을 캐시해 기본 및 발광 패스에서 재사용. 불필요한 임시 quaternion 생성 제거. 발광 마스크 UV가 실제 존재하는 32개 큐브만 발광 패스에서 렌더링(기본 패스는 전체 182개 유지). 실제 FPS 향상률은 미측정.
- 시각 포즈가 서버 머리 위치보다 약 3틱 지연될 수 있음. 이후 공격 판정은 서버 기준으로 동기화해야 함.
- 양쪽(서버/클라이언트)에 같은 모드 버전을 사용. 정지/재개 테스트 및 F3 FPS, /tick query TPS 비교 권장. 전체 게임 성능은 실제 환경에서 확인 필요.

## v0.7.2.3 관절 보정 및 그로기
- 하단 18개 다리의 원본 포즈에서 바깥 방향으로 꺾이는 구간을 인접 정상 포즈로 보정. 상단과 하단의 장축을 무릎/발끝 기준으로 정렬. 보간 이후에도 무릎을 연결하고 몸통의 국소 표면 법선 방향으로 하단이 반대로 향하지 않도록 제약. 발끝 위치는 일부 변경되므로 실제 접지 및 지형 간섭 확인 필요.
- 지상 경로를 304->204틱으로 재표본화(약 1.49배); 기존 공중/낙하 경로는 속도와 몸통 경로 유지. 원래 지상-공중 연결점과 낙하 착지점은 유지. 구형 NBT 프레임 번호는 새 번호로 변환.
- 정상 지상 순찰 중 강제 그로기 명령 및 공중 순환/직접 낙하 완료 때 자동 5초 그로기. 노란 체력바에 남은 시간을 표시하고 그동안 정지, 이후 자동 복귀. 수동 pause 상태에서는 그로기 시간도 정지. 그로기 중에는 새로운 특수 이동 예약 불가.
- 아직 전투 AI와 부위별 피해 판정은 없다. 그로기 중/외 피해량은 동일하고 무적이나 추가 피해를 부여하지 않음. v0.7.3 전투 시스템에서 주요 공격 후 자동 그로기 연결 예정.
- 이전 3틱 재생 버퍼 및 32개 발광 파츠 최적화 유지. 게임 전체 컴파일/실행 미검증. 이전 JAR와 중복 설치하지 말 것.
