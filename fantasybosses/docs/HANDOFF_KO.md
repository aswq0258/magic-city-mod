# FantasyBosses / 라디키온 통합 인계 명세서

**기준:** v0.7.5 (사용자 인게임 25/25 정상), v0.7.5.1 (BGM 추가, 빌드·인게임 검증 대기). Minecraft 1.21.1, NeoForge 21.1.267, GeckoLib 4.7.6, JDK 21, Gradle 9.2.1. 이 문서는 v0.7.5 실제 소스 및 사용자 테스트와 프로젝트의 기존 설계 결정을 바탕으로 작성했다. MagicCity/FantasyRPG/RoyalQoL의 최신 소스는 이번 작업에서 대조하지 않았으므로 아래 통합 API는 제안이며 실제 저장소 확인이 우선이다.

## 1. 인계 범위 및 보존 원칙
- FantasyBosses는 별도 JAR로 유지. MagicCity(월드·챕터), FantasyRPG(직업·피해량·성장), RoyalQoL(편의)과 호환되게 연결하고 하나의 JAR로 합치지 않는다. 통합 작업에서 기존 파일 및 API의 실제 구현을 먼저 확인한다.
- `fantasybosses:radicion`, `fantasybosses:root_organ`, `fantasybosses:brood_egg`, 기존 리소스 ID, 이동·공격 포즈, 11마디 피격, 6종 공격, 그로기, 전장 기능을 보존한다. 모델 원본은 blockbench/에 있다. GeckoLib 및 네오포지 버전은 현 모드팩과 비교한다.
- 이전 데이터팩은 정식 모드와 중복 실행 금지. 세계수 레지온을 수정하지 않는다. 데이터팩 잔여 모델은 백업 후 구 데이터팩의 stop 명령으로 정리. 원본 월드를 직접 수정하지 않고 복제본 및 테스트 인스턴스를 쓴다.
- v0.7.5.1에서는 오디오만 추가했다. v0.7.5로 롤백 가능한 태그/브랜치를 남겨라.

## 3. 검증된 전투 베이스라인 (20 TPS)
- 기본 체력 240 HP, 지상 204프레임(10.2초), 벽·천장 260, 직접 낙하 42. 평상시 지상 순찰, 공중은 지정 패턴에서만. `AIR_JOIN=239`, `DIVE_JOIN=394`, `DIVE_LAND=32`(낙하 내부 인덱스). 원본 경로/공격 포즈 바이너리와 모델을 변경하지 않는다.
- 페이즈 체력 기준 66%, 33%; 이미 진입한 페이즈는 회복으로 되돌아가지 않는다. 기관 활성 중 1페이즈 고정.

| 공격 | 시작 페이즈 | 예고(틱) | 범위(블록) | 피해(HP) | 그로기(틱) |
|---|---:|---:|---:|---:|---:|
| 턱 강타 | 1 | 18 | 4 | 6 / P3 8 | 30 |
| 흡수 | 1 | 24 | 5 | 5 | 60 |
| 꼬리 난타 | 2 | 22 | 4 | 7 | 40 |
| 직접 낙하 | 1 | 22 | 4/5/6 | 6 / P3 9 | 100 |
| 산란 | 2 | 26 | 3 | 0 (소환) | 100 |
| 벽면 돌진 | 2 | 22 | 5 | 10 | 100 |

지상 공격 대기 24/18/12틱, 공중 예약 기준 지상 누적 440/360/300틱. 공중 피해/타격은 실제 경로 프레임과 연결된다. 공격 텔레그래프와 타격을 분리하지 말 것. 그로기 외 완전 무적 금지(보호막 예외). 부위 피해 배율: 머리 1.0, 1~3마디 .70, 4~6 .85, 7~9 1.50, 꼬리 1.20. 그로기 ×1.25, 활성 기관 중 ×.60. 기본 RPG 피해 계산 앞뒤 순서는 기존 모드를 확인하고 단일 파이프라인에서 한 번씩만 적용한다.

### 전장 기믹
- P1: 기관 4개 각 24 HP, 100틱마다 기관당 2 HP 회복, 40% 피해 감소. 체력 하한은 최대체력×.6625 (기본 159 HP), 하한 도달 시 보호막 및 회복 정지. 전체 기관 파괴해야 해제, 대형 피해도 건너뛰지 못하게 유지. 기관 체력도 난이도 스케일링 여부를 별도 결정할 것.
- P2: 알집 8 HP, 60틱 부화, 알집 최대 3, 알집+유충 합계 6(로드 기준). 엔더마이트 임시 모델. 평화로움에서는 산란 실패. 소유자 UUID 기반 제거.
- P3: 균열 4곳에서 대각선 2구역 교대, 누적 대기 200틱, 예고 50틱, 반경 5·수직 ±3, 8 HP 마법 피해, 플레이어별 1회, 이후 그로기 60틱. 기존 공격과 중복 시작 금지.
- 사망: 공격 즉시 중단, 소유 개체/UI 정리, 48틱 동안 11마디 순차 소멸. 정상 사망과 관리자 제거/전투 실패/서버 종료를 구별해야 하며 보상과 클리어 처리는 아직 없음.

## 4. 위치와 이동 제약 (현재 실제 소스)
- 차원 `magiccity:kingdom`, 전장 x=-2895..-2825, y=7..40, z=-895..-825. 입구 테스트 좌표 -2860.5 9 -835.5, 보스 소환 -2861.179 9.518 -884.502.
- 기관 중심: (-2877.5,9,-859.5), (-2841.5,9,-859.5), (-2859.5,9,-872.5), (-2859.5,9,-843.5).
- 균열 조합: (-2871.5,9,-868.5)/(-2847.5,9,-851.5), (-2847.5,9,-868.5)/(-2871.5,9,-849.5).
- 지금은 한 전장에 한 마리, 원본 절대 좌표의 캡처 포즈. 이동 AI가 자유 지형을 탐색하는 것이 아님. `RadicionRoute.isArena`, `loaded`, `RadicionEntity.startRoute`, `readAdditionalSaveData`, `RadicionArena` 경계/기관/균열, `RadicionCombat.floor` 및 참가자 필터, 렌더러와 피격 위치 변환, `RadicionMusic` 경계를 반드시 함께 변경한다.
- v0.8 권장 구조: 원본 템플릿을 파티마다 별도 인스턴스로 복제하거나 차원/좌표 오프셋이 다른 동일 지형으로 배치. 원본 캡처 프레임은 불변으로 두고 전장 `origin + localOffset` 변환 레이어 도입. 서버·클라이언트 모두 같은 차원/원점/변환을 사용. 청크 준비 실패 때 전투 시작을 거부하거나 지연. 경로/기관/균열/피해 범위의 Y도 같은 변환 적용. 파티별 전장 실구현 방식은 MagicCity 소스 확인 후 결정.

## 5. 모드 간 계약 (제안; 기존 실제 API 확인 필요)
서버를 유일한 권한으로 삼는다. FantasyBosses가 직접 MagicCity/FantasyRPG 구현에 강결합하지 말고 초기에는 통합 어댑터 또는 공개 API로 연결한다. 순환 의존성 금지.

| 계약 | 입력·출력 | 책임 |
|---|---|---|
| 전투 시작 | encounter UUID, bossId, chapterId, dimension, arenaOrigin, 참가자 UUID 집합, 잠긴 진행 등급/난이도 | MagicCity/통합 어댑터가 시작 승인, FantasyBosses가 보스 생성 |
| 참가자 검증 | encounterId + player UUID | 파티 외부/관전자/사망/재접속 정책, 보스 AI와 피해·UI·BGM 공통 필터 |
| 피해 | encounterId, attacker UUID, DamageSource, segment, rawDamage, groggy, phase, attack kind | FantasyRPG 기본 피해 계산 후 보스 부위/그로기/기관 배율과 보호막 적용을 한 번만. 몹 공격에 진행 등급 배율 한 번만. 기존 피해 유형/속성 분류 등 실제 구현 확인 |
| 전투 종료 | encounterId, result(VICTORY/DEFEAT/ABORT), eligible participant snapshot | 완료 이벤트는 진짜 승리 시 한 번만. 퀘스트/보상 저장 및 중복 방지 키 |
| 저장/재접속 | encounterId, dimension, group, origin, grade, status, owner UUID, timers | 전투 인스턴스 상태의 소유권 단일화, 청크 재로드 후 고아 개체 정리 |
| 클라이언트 상태 | encounterId, boss entity ID, participant, active/ended, musicId | 로컬 BGM 및 UI를 현재 참가자의 전투에만 표시 |

프로젝트 기존 합의(소스 대조 필요): 1장 선행, 2~10장 자유, 11장 1~10장 완료+봉인 5개, 11~12장 6급 고정. 보스 시작 시 주변 참가자 중 최고 진행 등급을 고정. 공격력 배율 1~6급 8/11/14/15/17/18은 기존 설계값이며 실제 API/피해 산식에서 이미 적용하는지 확인한다. HP 배율 1.0은 임시안. 현재 독립 모드 240 HP/기본 피해량은 테스트 수치이고 이중 적용 금지. 정확한 세계수 챕터 ID 및 보상 ID는 코드와 기획 문서에서 확인하고 하드코딩 추측 금지.

## 6. 신규 BGM (v0.7.5.1)
- 이름 `Radicion – Under the Roots` / `뿌리 아래의 맥동`; 오리지널 절차 합성, 96초, 80 BPM, 44.1 kHz 스테레오, Ogg Vorbis. 외부 샘플 없음. 전용 리소스 `assets/fantasybosses/sounds/music/radicion_undercurrent.ogg`, `sounds.json`, 등록 ID `fantasybosses:music.radicion.undercurrent`. 재생성 스크립트 `tools/generate_radicion_bgm.py` (numpy/scipy/ffmpeg; 게임과 빌드에는 불필요).
- 현 단계: 로컬 플레이어가 원본 전장 경계 안에 있고 경로 활성/생존 라디키온이 로드되면 한 트랙을 상대좌표·비감쇠·Music 카테고리로 반복. 20틱 내외 볼륨 상승/사망 후 감소. 퇴장·차원 전환·사망한 플레이어·월드 전환·음악 음소거 시 즉시 정리. 음량 복구/리소스 재로드 후 다시 재생 시도. 크리에이티브도 테스트 가능; 관전자는 제외. 바닐라 상황 음악은 재생 중에만 SelectMusicEvent로 억제, 다른 효과음은 건드리지 않는다. 다른 음악 제어 모드와 충돌 가능성은 통합 검증 대상.
- 현재 참가자별 서버 패킷은 없음. v0.8에서 전장 좌표로 판단하는 코드 대신 서버에서 전달하는 encounter/participant 활성 상태를 사용하도록 교체. 멀티플레이 시 다른 파티의 음악 시작·중복 루프·리소스 재로드·보스 사망·재접속을 검사. 소리 파일 교체 시 같은 ID/형식 유지 또는 리소스 경로 동시 변경. 전체 컴파일/실게임 BGM 아직 미검증.

## 7. Claude 작업 순서 및 완료 조건
1. 독립 브랜치에서 현재 모드팩 소스/버전/API 목록과 v0.7.5.1 diff 검토. 먼저 기존 v0.7.5 재현 빌드, 이후 BGM 포함 빌드. 테스트 인스턴스에 설치. 게임 실행 로그 및 JAR 해시 기록. 실패하면 음악만 롤백 후 재검증.
2. 인스턴스 전장 컨텍스트 및 참가자 필터를 도입. 2개 파티 동시 전투 격리, 사망/퇴장/재입장, 서버 재시작, 청크 언로드, 비참가자 접근, PvE 투사체/범위 스킬, UI/소유 개체/BGM 정리 검증. 보스가 없거나 공격 불가 상태에서 BGM 시작 금지 여부는 전투 정책에 맞춰 결정.
3. RPG 피해·난이도 연동. 부위 히트박스 피해 중복, 회복/방어, 고단발 보호막, 원거리·다단히트·광역을 시험. 몹 공격 등급 고정과 파티 변동을 검증. RPG 실제 체력/피해 스케일로 전투 시간 재평가.

5. CI clean build 및 실제 클라이언트/전용 서버 실험. 원본 월드 변경 없음, FPS/TPS, 기존 모드 회귀 검사, 설치 파일 및 의존성 정리. 통합 완료 전 자동 빌드 결과와 게임 실행 결과를 분리해서 보고.
